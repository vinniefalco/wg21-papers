# Code review: build.py against build-script-spec

Change reviewed: the untracked `research/p4195/support/` files the spec names (`build.py`, `test_build.py`, `fixtures/`), judged by reading only.

1. `build.py` `render_proof` inserts a blank line at every change of block kind (heading to prose, caption to table rows, table rows to their citation line, list to prose), while the spec asks only for a blank line before a list that follows a table, a caption, or a prose line. `fixtures/expected.md` locks these extra blank lines in, so the emitted proof departs from the spec's layout wherever the source has those adjacencies. | rejected (main agent): kept on purpose since fix round 2, because without these blank lines markdown merges a table's citation line into the table and a prose line into the list item above it; the spec's "copies it unchanged" governs a prose line's text, not the spacing around it.

2. `build.py` `Source.__init__` takes a `text` parameter that no caller passes (`main` builds every `Source` from a path and `test_build.py` never constructs one), so the `if text is None` test is always true and the parameter is dead. | fixed: removed the unused `text` parameter, so `Source` always reads its file from the path.

3. `build.py` joins lines before matching, in `run_checks` for check 6 and in `forbidden` with `runs` for check 7, so a quote or multi-word phrase can span a line break, but no fixture wraps a Fact quote, a quoted string, or a forbidden phrase across lines. A line-by-line rewrite would still pass `test_check_6_fact_quote_missing_from_extract` and `test_check_7_forbidden_strings` while leaving wrapped Fact quotes unchecked or wrongly paired. | fixed: `fixtures/fail-6.md` adds `f:wrapped`, whose three quotes span two line breaks; `test_check_6_fact_quote_missing_from_extract` now expects its wrapped misquote "a poll binds the chair." at the opening line, while its wrapped quote that does match passes. `fixtures/fail-7.md` wraps "stack the room" across an item's lines and across two prose lines, and wraps a quoted "capture the room" in both places with "exploits" after it in the item; `fixtures/fail-7-front.md` wraps "of course" across two lines. Against an in-memory line-by-line version of `build.py`, both tests now fail: check 6 pairs the wrong quotes and reports "Then", and check 7 flags the quoted "capture" and misses every wrapped phrase.

4. `build.py` `run_checks` check 5 treats an item's subtree (`descendants`) as one unit and ignores citations from inside it (`inside`), but `fixtures/fail-5.md` has only one-level subtrees whose sole inside citation is the parent's own `proved by`. Narrowing the exclusion to the item alone, or stopping `descendants` at direct children, would still pass `test_check_5_orphan`, so an uncited parent whose children cite each other, and a parent whose only outside citation lands on a grandchild, are untested. | fixed: `fixtures/fail-5.md` adds `p:sibling-parent`, whose two children cite only each other, and `test_check_5_orphan` now expects it as an orphan at line 9. It also adds `p:grand-parent`, whose only outside citation lands on its grandchild `l:tally`, and the test expects no failure for it. In-memory versions of `build.py` that narrow the exclusion to the item alone, or stop `descendants` at direct children, now fail the test.

5. `build.py` `letters` and `roman` are tested only at ordinals 1 and 2 (`test_labels_continue_across_sources` reaches `10b` and `8b.ii`), so the spec's own `c` and `iii`, and every `ROMAN` entry past `i` such as `iv`, have no test that would fail if they broke. | fixed: new `test_letters_and_roman_numerals` checks `letters` at a, b, c, z, aa, az, ba, zz, and aaa, checks `roman` at every `ROMAN` entry plus 3, 14, 1994, and 3888, and prints labels for a source that reaches `1c` and `1c.iv`. Dropping the `iv` entry, or breaking `letters` past b, now fails it.

6. `build.py` `write` calls `os.makedirs` on the emit path's parent, creating directories the spec does not mention, and no test emits into a missing directory. | fixed: `write` no longer creates directories, since the spec asks only for the output file. An emit path whose folder is missing now prints "build.py: cannot write PATH: REASON" and exits 1, and new `test_emit_into_missing_directory` checks that message and that no folder appears; it failed before the fix.
