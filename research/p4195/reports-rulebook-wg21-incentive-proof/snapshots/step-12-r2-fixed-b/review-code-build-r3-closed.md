# Code review: build-script-spec

Reviewed the uncommitted change in `research/p4195/support/` (all untracked, `git diff` empty): `build.py`, `test_build.py`, and every file in `fixtures/`, judged by reading only. Three findings. The extra blank lines `render_proof` adds at block changes other than before a list are still not in the spec, but the round 2 fix kept them on purpose for markdown parsing, so they are not raised again.

1. `build.py` `run_checks` runs checks 2 and 3 only over item and table citations, so prose-line citations collected in `Source.cites` reach check 1 alone. An `In plain terms:` recap whose `from` citation names a later item therefore passes, though the spec's check 2 covers every `from` citation with no exception for prose lines, and no fixture has a prose line that cites forward. | fixed: each source line now records its place in the unit order, and `run_checks` applies checks 2 and 3 to prose and heading line citations too (a prose line has no children, so any `proved by` on one fails check 3). `fail-2.md` adds a prose line citing the next item, which fails, and one citing the item just before it, which passes; `fail-3.md` adds a prose line with a `proved by` citation.

2. `test_build.py` `test_check_7_forbidden_strings` only reaches forms from the -e and -ing branches of `build.py` `inflections` plus plain plurals, so the consonant-y (carried), -sh (punished), hyphenated (locked-in), and multi-word (stacked the room) forms built by `inflections` and `forms` have no case. It also has no negative case such as recaptured, so the whole-word lookarounds in `word_pattern` could be dropped with every test still passing. | fixed: `fail-7.md` adds punishes, stacked the room, carried, lock-ins, and locked-in, plus a line with recaptured and Clifford that must stay clean. Punishes replaces punished because the default branch also builds punished, so only punishes tells the -sh branch apart; lock-ins and locked-in cover both hyphen forms; recaptured guards the lookbehind and Clifford the lookahead. An in-memory mutation run confirmed the test now fails if either lookaround, the consonant-y, -sh, or multi-word branch, or either hyphen form is removed.

3. `build.py` `citations` and `CITE_OPEN_RE` recognize only the exact lowercase openers `*[from` and `*[proved by`, so a near-miss such as `*[From d:session]*` or `*[Proved by l:x]*` is silently treated as plain text. It raises no format error, is ignored by checks 1 through 5, and `emit` copies the raw key into the published proof. | fixed: `CITE_OPEN_RE` now matches openers case-insensitively and with loose spacing, and `citations` reports every opener that does not start a valid citation: the exact lowercase forms keep the open-and-close error, and any other form raises `malformed citation opener X; use *[from or *[proved by`, which fails the checks and so blocks emit. `malformed.md` adds `*[From`, `*[Proved by`, `*[ from`, and `*[proved  by` cases, and `test_format_errors` shows a near-miss in a front file stops emit from writing.
