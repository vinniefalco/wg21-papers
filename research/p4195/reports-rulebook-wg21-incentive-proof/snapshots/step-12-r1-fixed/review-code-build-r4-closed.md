# Code review: build.py against build-script-spec

1. **Beyond the spec.** `build.py` `render_proof` uses `BLOCKS` to insert a blank line at every change of block type (heading to prose, caption to rows, last row to the table's citation line, list to prose), but the spec asks only for a blank line before a list that follows a table, a caption, or a prose line, and says emit copies prose lines unchanged. `fixtures/expected.md` locks in the extra blanks. Some of them are what stop markdown from folding a table's citation line into the table and a recap into the item above it. | rejected (main agent): kept on purpose since fix round 2, because without these blank lines markdown merges a table's citation line into the table and a prose line into the list item above it; the spec's "copies it unchanged" governs a prose line's text, not the spacing around it.

2. **Beyond the spec.** `build.py` `main` prints `ok: mode M, N top-level items, N tables` after a clean check and `wrote PATH` after emit, while the spec defines check output only as one line per failure. `test_build.py` `test_check_token_is_not_a_source` locks in the ok line. | rejected (main agent): the ok and wrote lines report success only; failures still print one line each and exit 1, as the spec requires, and the steps rely on the ok line's top-level count to check the 150-item cap at a glance.

3. **Untested.** `build.py` `parse` lets blank lines sit between a table caption and its rows and between the rows and the citation line, and rejects rows that follow such a blank (`table_state` `'after'`); the spec's table format describes none of this. No fixture puts a blank line inside a table, so these transitions could break without a test failing. | fixed: kept the tolerance, since the kit's own worked table puts a blank line after the caption and before the citation line. `fixtures/proof.md`'s first table now uses that layout and the emit test still matches the unchanged `expected.md`; `fixtures/malformed.md` adds a table whose last row follows a blank line, and `test_format_errors` expects the "table must end" error on that row.

4. **Untested.** `test_build.py` `test_check_7_forbidden_strings` never uses nine of the nineteen forbidden words (perverse, railroad, steamroll, exploit, retaliate, outsider, cliff, obviously, door), and the only years it tests are 2025 and 2026. Dropping or misspelling one of those words in `build.py` `WORDS`, or changing `YEAR_RE` so it misses 1990 to 1999 or flags years outside 1990 to 2099, would still pass. | fixed: `fixtures/fail-7.md` adds prose lines using all nine words in their base form and the years 1989, 1990, 1999, 2099, and 2100; `test_check_7_forbidden_strings` expects each word and 1990, 1999, and 2099 to be flagged, and 1989 and 2100 to pass. Dropping a letter from any of the nine words in `WORDS`, or narrowing or widening `YEAR_RE` at either end, now fails the test.

5. **Swallowed error.** `build.py` `parse` reports a `1.` marker at an indent other than 0, 3, or 6 only when no item is open. If the item above has not reached its key yet and the marker sits at or past that item's content column (a nested item indented 4 spaces, or a fourth level at 9), the line is read as a continuation: the stray item merges into the open item, can supply its key, and neither the bad-indent nor the missing-key error appears. Emit then writes it as a nested list item with no label of its own, and no fixture covers the case. | fixed: `parse` now continues an open item only on lines with no `1.` marker, so a marker at any indent ends the open item; the item gets "item does not end with {#KEY}" and a bad indent gets its own error. `fixtures/malformed.md` covers a 4-space nested item and a fourth level at 9 spaces, each under an item that has not reached its key.

6. **Swallowed error.** `build.py` `parse` flags a stray `{#...}` marker only on prose and heading lines; one inside a table row, or mid-line in an item before its closing key, is neither reported nor removed, because `render` strips only the closing marker at the end of an item's last line. The spec's emit rule says to strip the markers, so such a marker would reach the emitted file. | fixed: a new `strays` helper runs when an item closes and when a table reaches its citation line, and reports "stray key marker" for any `{#...}` other than the item's closing key or the caption's own key, including one inside the caption text. Checks fail before emit, so no marker can reach the output. `fixtures/malformed.md` covers a mid-line marker on an item's first line, one on a continuation line, one in a caption's text, and one in a table row.

7. **Dead code.** `build.py` `cycle_path` ends with `return [start]`, which cannot run: `run_checks` only calls it on a strongly connected component that holds a cycle, so the breadth-first search always finds an edge back to `start` first. | fixed: removed `return [start]` and made the loop `while True`, with a docstring stating that `start` must lie on a cycle within `members`. `fixtures/fail-4.md` adds a self-citing lemma, so `test_check_4_citation_cycle` now also covers the one-member cycle `l:self -> l:self`.
